# ترحيل بيانات eStock إلى PharmacyPOS

**التاريخ:** 2026-11-24
**المصدر:** `F:\e-Stock_Backup.bak` (SQL Server backup — قاعدة `stock_Data`، حجم 224MB)
**الأداة:** `tools/estock-converter` (محوّل قابل لإعادة الاستخدام)
**النطاق المطلوب:** الأصناف والأدوية والباركود والموردون **غير الموجودين** في النظام الحالي فقط.

## 1. نتيجة الترحيل

| البند | قبل | بعد |

| إجمالي الأصناف | 27,617 | **72,389** |
| أصناف مستوردة من eStock | — | **44,772** |

- الأصناف الموجودة عندك **لم تُعدَّل ولم تُحذف** — لا تغيير على أسعارها أو أرصدتها.

## 2. كيف قُرئت بيانات eStock

| حقل eStock | المعنى | مقابل PharmacyPOS |
|---|---|---|
| `Products.sell_price` | سعر العلبة | `price_box` |
| `Products.unit2_sell_price` | سعر الشريط | `price_strip` |
| `Products.unit3_sell_price` | سعر الوحدة الصغرى | `price_unit` |
| `Products.product_unit1_2` | عدد الشرائط في العلبة | `strips_per_box` |
| `product_unit1_3 ÷ product_unit1_2` | عدد الوحدات في الشريط | `units_per_strip` |
| `Products.product_int_code` | الباركود | `barcode` (يُترك NULL إن لم يوجد) |
| `Product_Amount.amount` | رصيد الدفعة (بالعلبة) | `stock_boxes/strips/units` + دفعة في `purchase_items` |
| `Product_Amount.buy_price` | تكلفة العلبة | `purchase_items.net_box_price` / `unit_net_cost` |
| `Product_Amount.exp_date` | الصلاحية | `purchase_items.expiry` (MM/YYYY) |
| `Vendor.vendor_current_money` | رصيد المورد | `suppliers.balance` |

كل الدفعات المستوردة تحمل `batch_no = ESTOCK-<pa_id>` و`purchase_id = OPENING-ESTOCK-20261124`
(فاتورة شراء واحدة باسم «رصيد افتتاحي — استيراد eStock») حتى يعمل **FEFO** ويُحسب الربح
من التكلفة الحقيقية لكل دفعة لا من سعر تقديري.

> **تحديث لاحق:** بناءً على طلب العميل أصبح الترحيل **كتالوج فقط**: أُزيلت دفعات
> الاستيراد وفاتورة الرصيد الافتتاحي، وصُفِّرت أرصدة كل الأصناف المستوردة،
> وأصبح الكتالوج (72,389 صنفاً) **ثابتاً ومدمجاً في البرنامج** يُثبَّت مع أي نسخة جديدة.
> راجع القسم 7.

## 3. ملاحظات على جودة بيانات المصدر

- **26 دفعة منتهية الصلاحية** و183 تنتهي خلال 6 أشهر و172 بلا تاريخ صلاحية — ظهرت في شاشة «تواريخ الصلاحية».
- **48 صنفاً** سعر الشريط فيها لا يساوي (سعر العلبة ÷ عدد الشرائط) بسبب تقريب في eStock نفسه؛ أُبقي السعر كما هو في المصدر.
- **2 صنف** بلا سعر (`price_box = 0`) — يظهران بشارة «غير مسعّر».
- **13,995** صنفاً جديداً بلا باركود في eStock (اسم فقط) — يمكن إضافة باركود لها لاحقاً.
- تصنيفات eStock (المجموعات) غير دقيقة لبعض الأصناف، وقد تظهر تصنيفات غريبة (مثل شامبو تحت تصنيف دوائي) — هذه بيانات المصدر كما هي.
- **لم تُرحَّل** فواتير البيع التاريخية (92,606 فاتورة) ولا أرصدة العملاء (167 عميلاً) — لم تكن مطلوبة في هذه المرحلة، وملفها جاهز في مخرجات المحوّل إن رغبت لاحقاً.

## 4. الأداة القابلة لإعادة الاستخدام

المجلد: `tools/estock-converter`

```
convert.bat            ← انقر عليه (يرفع الصلاحية تلقائياً)
convert.ps1            ← منطق التحويل (استعادة → قراءة → JSON → حذف القاعدة المؤقتة)
README.md              ← دليل الاستخدام
```

**الاستخدام لأي صيدلية أخرى:** شغّل `convert.bat` → اختر ملف `.bak` → ينتج
`eStock-Import.json` بجانب الملف → في البرنامج: الإعدادات → النسخ الاحتياطي →
«استيراد كتالوج من برنامج آخر (eStock)» → مراجعة الأعداد → تأكيد.

- الاستيراد يحدّث الأصناف المتشابهة ويضيف الجديد، ويحتاج صلاحية **مدير النظام**.
- يسجّل العملية في سجل التدقيق باسم `IMPORT_EXTERNAL_CATALOG`.
- متطلب الأداة: SQL Server Express (المثيل `SQLEXPRESS`) على جهاز التحويل فقط.

## 6. التحقق

- اختُبر الاستيراد ثلاث مرات: دفعة كاملة (44,772 صنفاً)، ودفعة مكررة، وملف اختباري صناعي ثم حُذف بالكامل.
- لا يوجد أي أثر لبيانات الاختبار: `trade_name LIKE 'IMPORT TEST%'` = 0، موردون تجريبيون = 0، دفعات `IMP-%` = 0.
- شاشة الأصناف: 72,389 صنفاً، بحث «SELSUN» يعمل، الأعمدة مستقرة بارتفاع 71px.
- شاشة تواريخ الصلاحية: 615 دفعة مستوردة بتواريخها وكمياتها وقيمها.

## 7. تحديث: كتالوج ثابت بدون رصيد (2026-11-24)

بناءً على طلب العميل، تغيّر سلوك الترحيل والاستعادة:

### أ) الكتالوج أصبح ثابتاً ومدمجاً في البرنامج
- ملف جديد `public/catalog-v1500.json` يحتوي **72,389 صنفاً** بكل بياناتها
  (الاسم العربي/الإنجليزي، الاسم العلمي، الباركود، الأسعار الثلاثة، التعبئة،
  التصنيف، المورد المفضل، نوع الوحدة) **وبدون أي رصيد أو دفعات أو تواريخ صلاحية**
  (`stock_boxes/stock_strips/stock_units` = 0 و`expiry` = NULL).
- عند تثبيت البرنامج على أي جهاز جديد يُثبَّت هذا الكتالوج تلقائياً
  (`_runFullCatalogMigration` بمفتاح `full_catalog_v1500_applied`).
- 41,075 صنفاً منها لها باركود، و31,314 بلا باركود (بيانات المصدر).

### ب) أُزيلت أرصدة ودفعات الاستيراد
- حُذفت 615 دفعة استيراد من `purchase_items` وفاتورة `OPENING-ESTOCK-20261124`.
- صُفِّرت أرصدة كل الأصناف المستوردة (`source_code='ESTOCK'`): 0 علبة/شريط/وحدة.
- بقي 3 بنود شراء أصلية فقط (بيانات ما قبل الترحيل) دون تغيير.

### ج) الاستيراد والاستعادة يحدّثان الأصناف المتشابهة
- **استرجاع نسخة احتياطية (JSON):** النسخة الاحتياطية هي المصدر للحقول — أي صنف
  موجود فيها يُكتب بأسعاره وباركوده ورصيده كما في النسخة. ثم يُضاف من الكتالوج الثابت
  أي صنف غير موجود في النسخة (بدون رصيد)، فلا يقلّ العدد أبداً عن 72,389.
- **استيراد كتالوج خارجي (eStock):** يضيف الجديد ويحدّث السعر/التعبئة/الاسم/التصنيف
  للأصناف المتشابهة (بالباركود ثم الاسم)، **ولا يغيّر الأرصدة ولا ينشئ دفعات**.

### د) نتائج التحقق
- محاكاة تثبيت جديد على قاعدة فارغة: 72,389 صنفاً، 41,075 بباركود، 0 رصيد.
- محاكاة استرجاع نسخة بها صنف معدّل + صنف جديد: السعر والرصيد تغيّرا حسب النسخة،
  وأُضيف الصنف الجديد، وبقي الكتالوج كاملاً (72,390 = 72,388 + 2).
- محاكاة استيراد خارجي: تحديث السعر/التعبئة لصنف مطابق، وإضافة صنف جديد برصيد صفر،
  دون إنشاء أي فاتورة شراء أو دفعة.
- `npm run build` ناجح.
